# 요구사항 명세 (P1) — CER App

음성인식 장비(ZIEUM STT) 연동 CER/WER 시험 프로그램.
근거: docs/spec/zieum_기술문서.pdf, data/input 샘플. 인터페이스 상세는 interface_summary.md 참조.

## 기능 요구사항 (FR)
| ID | 요구사항 | 근거 |
|---|---|---|
| FR-01 | 음성(`.wav`) 폴더와 정답 전사(`.txt`) 폴더를 각각 지정할 수 있다(전사 폴더를 비우면 음성 폴더와 동일). 각 폴더의 한 단계 하위 폴더까지 탐색해 동일 기본 이름의 쌍을 로딩한다(같은 상대 경로 우선, 없으면 전사 폴더에서 이름으로 검색). 파일명 규칙은 없다(문장 단위 모드에서 `_rx`/`_tx` 구분 불필요). 쌍이 맞지 않는 파일은 경고 후 제외, 수만 건에서도 동작해야 한다 | input/README, 사용자 결정 |
| FR-02 | WAV를 검증한다(8kHz, mono, PCM16). 불일치 시 오류 또는 변환 | Spec 4.4.3 |
| FR-03 | 설정(서버 IP/포트, API 키, 모델 v1/v2/v3, EPD·결과 옵션)을 설정 파일/환경변수로 받는다. API 키는 코드/문서에 하드코딩하지 않고 로컬 설정 파일(저장소 제외, .gitignore)에 보관하며 GUI에서 입력·변경한다(화면에는 마스킹) | Spec 4.1~4.4 |
| FR-04 | `/health` 확인 후 WebSocket으로 ready → PCM 청크(3200B, 0.2s 페이싱) → finalize 순서로 전송한다 | Spec 4.4.1~4.4.2 |
| FR-05 | 최종 transcript와 segments를 수신·저장한다(`data/results`). 오류(401/400/404/500)·연결 끊김은 파일별로 기록하고 배치는 계속 진행한다 | Spec 4.4.6 |
| FR-06 | 화자(파일)별로 독립 평가하며, 정답 TXT와 인식 결과를 정규화 후 비교해 CER(S/I/D/N 포함)을 산출한다 | Spec 2.1 |
| FR-07 | 동일 데이터로 WER(어절 단위)을 산출한다 | 프로젝트 목적 |
| FR-08 | 리포트를 CSV·JSON·요약 텍스트로 출력한다(파일별 상세 + 화자(rx/tx)별·전체 평균 CER/WER) | 프로젝트 목적 |
| FR-09 | 모델(model_v1~v3)을 선택·비교 실행할 수 있다 | Spec 4.4 |
| FR-10 | 배치 실행(폴더 단위)을 지원하고 진행 상황을 표시한다 | 프로젝트 목적 |
| FR-11 | **웹 화면(브라우저 UI)** 탭 구성으로 실행·결과 출력: ① 설정·실행 ② 실시간 결과 ③ 파일별 결과 ④ 상세/리포트. 입력 폴더/모델/서버 설정 지정, 진행 표시, 화자별·전체 CER/WER 표시, 리포트 저장. 상태줄은 모든 탭에 항상 표시 | 사용자 결정 |
| FR-12 | 시험 시작 전 옵션으로 **시험 모드**를 선택한다: ① 일반(장시간 통화 파일, 화자 분리) ② 문장 단위(평균 7초 내외 음성, 수천~수만 건). 자동 판별하지 않는다 | 사용자 결정 |
| FR-13 | **응답 속도 측정(문장 단위 모드에서만 동작, 옵션으로 켜고 끔. 실시간 페이싱을 해제하면 비활성+경고)**: 파일별로 문장 입력 종료(마지막 청크 전송/`finalize`) → 최종 인식 결과 수신 완료까지의 시간을 기록한다. 음성 길이가 30초 이상인 파일은 속도 측정·집계에서 제외(CER/WER은 평가)하고 제외 건수를 표시한다. 집계: 문장 단위 시험 전체 파일(30초 이상 제외)의 평균을 대표값으로 하고 중앙값·최대·p95를 함께 표시한다 | 사용자 결정 |
| FR-14 | **동시 접속**: CER 측정만 할 때 기본 4, **응답 속도를 측정할 때는 기본 1**(서버 부하 영향 배제)로 병렬 인식한다. GUI에서 변경 가능하며 서버 허용 수 이내로 제한한다. 리포트에 동시 접속 수를 기록한다 | 사용자 결정 |
| FR-15 | **이어서 하기**: 중단·재실행 시 이미 완료된 파일은 건너뛴다(수천~수만 건 대응) | 규모 요구 |
| FR-16 | **대량 결과 조회**(스크롤 방식 가상 목록): 파일명 검색, 상태·화자 필터, CER/WER 기준 정렬, CER 구간별 분포, 오류율 상위 N개를 제공한다. 전체 상세는 CSV로 저장한다 | 규모 요구 |
| FR-17 | **진행 중 실시간 결과**: 시험이 진행되는 동안 누적 CER/WER(가중)과 완료 건수 기준 CER 추이(그래프), 최근 N건 구간 CER을 주기적으로 갱신해 표시한다. 응답 속도 평균도 같은 방식으로 갱신한다. 중간 스냅샷은 파일로도 저장해 비정상 종료 시에도 확인할 수 있다 | 사용자 결정 |

## 비기능 요구사항 (NFR)
| ID | 요구사항 |
|---|---|
| NFR-01 | 시험 결과는 재현 가능해야 한다(설정·모델·시각을 결과에 함께 기록) |
| NFR-02 | 인증정보는 로그·리포트에 출력하지 않는다 |
| NFR-03 | 한글(UTF-8) 처리, 입력 TXT 인코딩 오류 시 명확한 오류 메시지 |
| NFR-05 | 수만 건 규모에서도 GUI가 멈추지 않고(백그라운드 실행, 일괄 갱신) 메모리를 과다 사용하지 않는다 |
| NFR-04 | 연결 실패 시 재시도 횟수·타임아웃을 설정할 수 있다 |

## 입력 데이터 관찰 (data/input 샘플)
- 화자 분리된 연속 통화 녹음: rx/tx가 화자별 파일로 분리되어 있고(파일 쌍마다 해당 화자의 정답 TXT), 약 5.2MB WAV(8kHz mono 16bit 가정, 검증 필요)
- 정규화 방침(확정): 추임새("음", "네" 등)는 비교에서 제외하고, 숫자 표기 차이(한글/아라비아)는 무시한다. 추임새 목록과 숫자 변환 규칙은 설계(P2)에서 상세화
- 시험용 샘플(수백 개)은 5분 이상 장시간 통화 파일이며, 실제 CER 측정 데이터는 7초 내외 문장 단위 음성 수천~수만 개이다
- 일반 모드: 연속 음성이므로 문장 정렬 없이 파일 전체 텍스트 단위로 비교한다 / 문장 단위 모드: 파일 1건 = 문장 1개로 건별 비교
- 정답 TXT에 빈 줄, 추임새("음", "네"), 숫자 한글/아라비아 혼용("육육이에 3 1") 존재 → 정규화 규칙 필요
